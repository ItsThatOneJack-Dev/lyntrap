## Reporting a Vulnerability

**Please do not report security vulnerabilities through public GitHub issues, discussions, or pull requests.**

If you believe you have found a security vulnerability in Lyntrap, please use GitHub's **Private Vulnerability Reporting** feature:

1. Go to the repository's **Security** tab.
2. Select **Advisories**.
3. Select **Report a vulnerability**.
4. Provide as much information as possible about the vulnerability.

Reports submitted through this mechanism are private and are only visible to the relevant maintainers and the reporter while the vulnerability is being investigated.

If Private Vulnerability Reporting is unavailable, please contact the maintainer privately before disclosing any details publicly.

### What to include

Please provide:

* A description of the vulnerability.
* The affected version(s), commit(s), or components.
* Steps to reproduce the issue.
* A proof of concept, if applicable.
* The expected and actual behaviour.
* The security impact and potential attack scenarios.
* Any suggested mitigation or fix, if you have one.

Please avoid including secrets, credentials, or personal information that are unrelated to demonstrating the vulnerability.

## Coordinated Disclosure

Lyntrap follows a coordinated disclosure process.

After receiving a report, the maintainers will investigate and work with the reporter to understand and remediate the vulnerability. Where appropriate, a patched release will be prepared before public disclosure.

The timing and contents of public disclosure will be coordinated between the reporter and maintainers where possible.

Security researchers will be credited for responsible disclosures unless they request otherwise.

## Scope

This policy applies to security vulnerabilities in Lyntrap itself and its officially distributed components.

For ordinary bugs, feature requests, questions, and other non-security issues, please use the normal GitHub issue tracker.
